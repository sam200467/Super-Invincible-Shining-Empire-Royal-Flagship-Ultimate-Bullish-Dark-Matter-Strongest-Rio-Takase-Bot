# Rio Chat

An optional chat module. When enabled, the bot replies to direct mentions with text generated by the DeepSeek API from a persona prompt, rather than drawing from a fixed pool of quotes.

Chat is **off by default** and stays off until you create `config.local.json` in this directory with `enabled: true`. If the configuration is missing or invalid, the module is skipped and the slash commands keep working.

## What this repository includes

This release ships the implementation only. The persona, the example dialogues, the expression manifest and the emoji images are deployment content and are not part of this repository, so the module cannot be enabled without adding your own files first.

| File | Included | Purpose |
| --- | --- | --- |
| `chat.cjs` | yes | Configuration validation, DeepSeek calls, Discord message handling, sessions and image selection. |
| `chat.test.cjs` | yes | Offline tests against a mocked API. Skips itself unless the deployment files below are present. |
| `config.example.json` | yes | Template with chat disabled and no API key. |
| `persona.md` | no | System prompt for the character. **Required to enable chat.** |
| `examples.json` | no | `{"examples": [...]}` of style examples used to steer generation. **Required to enable chat.** |
| `expressions.json` | no | Image whitelist and selection probabilities. Required only when `expressions.enabled` is true. |
| emoji image files | no | Referenced by `expressions.json`. Required only when `expressions.enabled` is true. |

## Enabling chat

1. Create your own `persona.md` and `examples.json` in this directory. `persona.md` is read up to a `## 证据索引` heading, if present.
2. Copy the template and fill it in:

```powershell
Copy-Item rio-chat/config.example.json rio-chat/config.local.json
```

3. Set `enabled` to `true` and put your DeepSeek API key in `provider.apiKey`. Leave `expressions.enabled` as `false` until you have also supplied `expressions.json` and its image files.
4. Restart the bot. The startup log should report that chat is enabled.

`config.local.json` is listed in this directory's `.gitignore`. It holds your API key in plain text — never commit it, paste it into an issue, or ship it in a release. The key is not embedded in any executable.

The provider block is validated on load: the base URL must be `https://api.deepseek.com`, the endpoint `/chat/completions`, and the key must be non-empty. Numeric settings are range-checked, and the module refuses configurations other than a mention-triggered, non-DM, in-memory setup.

## Talking to it

Mention the bot directly in a channel it is already configured for:

- `@bot recommend me some songs`
- `@bot reset chat`

Only messages containing a direct user mention are matched. The bot does not read channel history, does not respond in DMs, and ignores other bots and webhooks. Direct mentions are covered by Discord's message content exception, so the privileged **Message Content intent is not required**.

A per-channel allowlist (`discord.allowedChannelIds`) can narrow this further; leaving it empty means every channel already configured for the bot.

Replies are usually a few sentences. The persona and the recent conversation are sent to the DeepSeek API, which is billed per usage. The bot's configured HTTP proxy, if any, is used for these requests too.

## Sessions and limits

Sessions are isolated per guild, channel and user. Each keeps the last 6 turns, expires after 30 minutes of inactivity, and is additionally capped at about 12000 characters of history. Sessions live in memory only and are cleared when the process restarts; at most 500 are retained.

`reset chat` clears the current session only. A per-user "stop teasing" preference persists until the process ends or the user explicitly allows it again.

One request per user is processed at a time; additional messages are told to wait. Chat concurrency is separate from the chart generation queue. Defaults are two concurrent requests overall and a 5 second cooldown per session after a successful reply — these limit API usage, not image generation. Paid requests are not retried automatically, and a model timeout or malformed response produces a short failure message rather than a raw error.

Natural language score lookup is not implemented; use the `/song`, `/chart` and related slash commands.

## Expression images

Expression images are optional and disabled in the template. When enabled, `expressions.json` supplies the whitelist and the four selection probabilities, and every entry's file path is resolved and confined to this directory — a path escaping it is rejected. The model may propose a candidate id, but only ids present in the manifest are accepted; the bot never opens a model-supplied file path. If the bot lacks permission to attach the file, it sends text only.

## Testing and building

From the repository root:

```powershell
node --test rio-chat/chat.test.cjs
node build-discord-bot.js
```

Without the deployment files above, the chat suite reports as skipped. The build also runs the alias store, startup retry and core self-tests.
