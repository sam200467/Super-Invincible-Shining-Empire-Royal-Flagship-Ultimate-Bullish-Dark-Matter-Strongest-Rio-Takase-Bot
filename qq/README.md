# Takase Bot — QQ 版

用自己的 QQ 小号当机器人，在群里查音击分数、生成分表图片，并支持与 Discord 版相同的梨绪聊天。

**协议端**：NapCat（NTQQ 无头 + OneBot 11）。**不经过** QQ 开放平台。

> 与 Discord 版共用 `takase-core.cjs`（曲库检索、定数计算、凭据库、渲染调用）。
> 两边功能独立、互不影响。

---

## ⚠️ 先读这段

个人号挂第三方协议端**违反腾讯的服务条款**，账号可能被警告、冻结甚至封禁。这不是危言耸听，是这类方案的固有代价。

降低风险的做法：

- **只用小号**，别用主号，做好这个号会丢的准备
- **老号远比新号稳**。新号基本会被冻几次（解封要扫脸）—— 新号先正常聊天养几天再挂
- **在家宽上跑**。机房/VPS 的 IP 风控严重得多
- **QQ 登录绝不能走代理**（机器人访问 u.otogame 可以走）
- 代码层面已做限流（每群每小时 20 条、每用户 30 条、每日 1500 条上限、风控熔断），但**只能降低触发概率，消除不了风险**
- 只加小群、可信的群。被群友举报是封号最快的路径

## 首次配置

### 1. 装并登录 NapCat

下载 `NapCat.Shell.Windows.OneKey.zip` 或 `NapCat.Shell.zip`（[Releases](https://github.com/NapNeko/NapCatQQ/releases)），解压到**纯英文路径**。

双击 `launcher-win10-user.bat`（Win10/11 用 win10 变体；非管理员版就够，失败再试 `launcher-win10.bat`）。首次会显示二维码，**用小号扫码登录**。

> NapCat 要求特定的 QQ 版本，太新会报 `PacketBackend 不支持当前QQ版本架构`。
> **这个报错可以忽略** —— 它只是附加功能（群头衔、poke 等）不可用，收发消息正常。

### 2. 在 NapCat 里配 OneBot 网络

打开 NapCat 的 WebUI（一般是 `http://127.0.0.1:6099/webui`，密钥在 `napcat/config/webui.json`），进「网络配置」，加一个**反向 WebSocket 客户端**：

| 字段 | 填 |
|---|---|
| 名称 | `takase` |
| URL | `ws://127.0.0.1:8790/onebot` |
| Token | 自己生成一串（要和 `qq-config.json` 里的一致） |
| messagePostFormat | `array` |
| reportSelfMessage | 关 |
| 重连间隔 | 5000 |

⚠️ **不要再额外开一个正向 WS 到同一个机器人** —— 每条消息会被处理两次，账号看起来就像 spammer。适配层会拒绝第二个并发连接并在日志里警告。

也可以直接改配置文件 `napcat/config/onebot11_<QQ号>.json`，改完**必须重启 NapCat**（它不热加载）。

### 3. 改 `qq-config.json`

```jsonc
{
  "napCatLauncher": "…/NapCat/launcher-win10-user.bat",  // 供 启动NapCat.vbs 用
  "oneBotPort": 8790,          // 要和 NapCat 里的反向 WS 端口一致
  "oneBotToken": "…",          // 要和 NapCat 里的 token 一致
  "qqNumber": "…",             // 机器人 QQ 号（启动时会自检，不一致会告警）
  "allowedGroupIds": ["…"],    // 允许使用的群号，必填；为空拒绝启动
  "workDir": "…/qq/data",      // 数据目录（绑定库、别名库、临时图片）
  "corePath": "…/ongeki-core.exe",
  "vaultHelperPath": "…/takase-discord-vault.exe",
  "vaultPath": "…/qq/data/bindings.dat",
  "proxyUrl": "http://127.0.0.1:7897"   // 抓分用；OneBot 本地连接不走它
}
```

### 4. 打包并启动

```bash
node qq/build-qq-bot.js
```

推荐直接双击 **`Takase Bot QQ.exe`**：界面里可以保存配置、启动 NapCat、启动/停止 Bot、查看日志与绑定人数，也支持托盘和开机自启。配置和 Token 使用 Windows DPAPI 加密保存在当前用户目录。

界面上有两盏**独立的状态灯**，据此决定这次要启动几个程序：

| 灯 | 含义 |
|---|---|
| `NapCat：未启动` | 没检测到 NapCat 进程，直接点「启动 Bot」会一直等，先启动 NapCat |
| `NapCat：已启动` | NapCat 进程在跑，但还没连上 Bot（Bot 没启动，或 OneBot 反向 WS 没配好） |
| `NapCat：已连接` | 已连上 Bot（绿），全链路通了 |
| `Bot：未启动 / 等待 NapCat 连接…… / 运行中 / 正在生成…` | Bot 自己的状态；生成中会显示当前任务 |

所以日常「NapCat 已经在跑，只想重启 Bot」时，点「启动 Bot」就行，不用管 NapCat。
NapCat 那盏灯里的「已连接」来自 Bot 主动上报，只有 Bot 在跑时才有；进程检测则是独立做的，Bot 没启动也能亮。

旧的无窗口启动方式仍然保留：依次双击 **`启动NapCat.vbs`** → 等十几秒 → **`启动QQBot.vbs`**。

两者都是无窗口后台运行。Bot 的日志在同目录 `bot.log`。

> 需要用二维码重新登录时，**直接双击 `launcher-win10-user.bat`**（有窗口才看得到二维码），
> `启动NapCat.vbs` 是给日常无窗口运行用的。

## 命令

| 命令 | 场景 | 说明 |
|---|---|---|
| `#帮助` | 群 · 私聊 | 功能清单 |
| `#绑定` | **私聊** | 绑定大饼账号（群里发会引导你私聊） |
| `#分表` | 群 · 私聊 | 生成 B50 + N10 + P50 分表 |
| `#牌子 <版本>` | 群 · 私聊 | 生成版本牌子的全曲完成度图；不带参数可查看版本列表 |
| `#单曲 <曲名或ID>` | 群 · 私聊 | 生成单曲全难度成绩图 |
| `#谱面分析 <曲名/ID 难度>` | 群 · 私聊 | 生成分数线、判定容错与白金分分析图 |
| `#定数表 <14或14.2>` | 群 · 私聊 | 查询定数表，无需绑定 |
| `#等级 <条件> [页码]` | 群 · 私聊 | 按 14/14+/14.1/ABFB 查询等级成绩 |
| `#计算 <定数> <技术分> <铃铛> <连击>` | 群 · 私聊 | 计算单曲 Rating |
| `#添加别名 <曲目> \| <别名>` | 群 · 私聊 | 添加歌曲别名 |
| `#删除别名 <曲目> \| <别名>` | 群 · 私聊 | 群主/管理员删除歌曲别名 |
| `#查看别名 <曲目>` | 群 · 私聊 | 查看歌曲全部别名 |
| `#是什么歌 <别名>` | 群 · 私聊 | 按别名反查歌曲 |
| `#允许查询` / `#禁止查询` | 群 · 私聊 | 开/关「群友能不能查我的成绩」，**默认关** |
| `#状态` | 群 · 私聊 | 队列与连接状态 |
| `#解绑` | 群 · 私聊 | 删除绑定（60 秒内再发一次确认） |
| `#取消` | 私聊 | 中断进行中的绑定流程 |

各功能同时接受对应的英文 Discord 命令名，例如 `#song`、`#plate`、`#level`、`#calculate`。
`#` 可以用全角 `＃` 或 `/` 代替，ASCII 关键字不区分大小写。

**群里必须带前缀**，裸关键字不触发（避免对闲聊响应，也压低风控）。私聊里可以省略。

### 梨绪聊天

在允许群里直接 **@机器人 + 文字** 即可聊天。聊天使用与 Discord 版相同的角色设定、上下文、冷却、DeepSeek 配置和表情选择逻辑；普通群消息不会触发。需要先配置并启用 `rio-chat/config.local.json`。

### 用大白话查分

带 `#` 前缀的指令照旧全部可用，但**不背命令也能查**：直接在群里 @机器人 说人话就行。

```
@机器人 你现在有哪些功能？
@机器人 你能不能帮我查一下 id870 这首歌全难度成绩图
@机器人 闪击牌子我还差多少
@机器人 14.2 打 1000737 分能有多少 rating
```

模型只负责判断「用户想用哪个功能、参数是什么」，成绩、定数、图片都由程序按真实数据发出；
模型那句话（比如「哼哼，这就去翻你的成绩」）只是先发出去的引出语。

- 覆盖范围：功能清单、单曲成绩图、B50 分表、等级成绩、牌子完成度、谱面分析、定数表、Rating 计算
- **不含**绑定、解绑和别名管理 —— 那些要收邮箱密码或改共享数据，仍然只走明确指令
- 和 `#` 命令共用同一套解析、队列与冷却：聊天触发的生成同样会占队列、同样有 60 秒冷却
- 未绑定、冷却中、找不到曲子这类失败会发一条确定性说明，此时**不会**把模型那句引出语发出去，避免前后矛盾
- 闲聊、问身份、拿不准要查什么时不会触发任何查询

### 它能接住群里的上下文

@ 它之前群里说过的话，它会一起读到（最近 12 条 / 10 分钟内），所以「这个人是不是有点弱」「刚才那张图是谁的」这类指代能接上。

它自己出的图**连图上的数据一起记**：

```
20:17 梨绪：DEMO PLAYER 的单曲全难度成绩：id870 VIIIbit Explorer｜MASTER 1008123 AB · FC · FB（图片）
20:17 梨绪：DEMO PLAYER 的 B50 + N10 + P50 分表｜RATING 16.749 · 三榜 50/10/50 曲 · 榜首 …（图片）
```

所以「他这首歌打了多少」「B50 里最高的是哪首」这类追问答得上——图本身聊天模型读不到，但**生成图用的那份数据读得到**。

- 只记群里本来就公开可见的内容；**别人发的图片只记「有人发了图」，读不到图里的内容**（模型没有视觉能力），只有自己生成的图带数据
- 上下文只用于理解指代，不会逐条回应或复述
- 超过 10 分钟或 12 条之外的会被丢掉；重启 bot 清空
- 这段内容会随消息一起发给 DeepSeek，和聊天本身走同一条链路

### 查群里别人的成绩

@ 上对方就行：

```
@机器人 帮我查一下 @某人 的闪击牌子
@机器人 @某人 这首全难度打了多少
```

也可以走指令：`#单曲 @某人 id870`、`#等级 @某人 14+`。

**默认谁都查不到别人** —— 想被查要本人自己开：

| 情况 | 结果 |
|---|---|
| 对方没绑过账号 | 回「TA 还没绑定过」，查不了 |
| 对方没开 `#允许查询`（默认） | 回「TA 没开放成绩查询」，并提示对方怎么开 |
| 对方开过 | 用**对方自己的账号**取数，图片说明里写明是谁的 |

技术上查别人就是用对方存的账号密码登录（u.otogame 没有公开的按玩家查询接口），所以这道开关是隐私红线，不是可选项：
别人触发登录，风控风险算在对方账号上。查询对象只认**本条消息真的 @ 过的人**，模型编不出一个不存在的人来查。

### 设计与 Discord 版的差异

QQ 个人号没有斜杠命令、按钮、弹窗，也没有消息编辑 API，所以：

- **一次回复变成两条消息**：先发「已收到，正在生成……」，完成后另发图片。默认**不撤回**占位消息 —— QQ 撤回自己的消息会留下「撤回了一条消息」的系统提示，比留一条过期的占位更糟
- **绑定改成私聊状态机**：邮箱和密码**分两条消息收**，密码那条方便你长按撤回
- **密码卫生**：机器人不回显、不写日志（有测试专门断言这点），但**消息本身会留在你的 QQ 聊天记录里 —— 发送后请手动撤回**
- **解绑用二次确认**代替按钮
- 图片走**临时文件 + `file:///`** 直传（`qq/data/outbox/`，发送后立即删除，启动时清扫 1 小时以上的残留）

## 排查

**Bot 没反应**
1. 看 `qq/bot.log` 有没有 `BOT_READY`
2. 双击 `启动NapCat.vbs` 后等十几秒再启动 Bot —— Bot 要先监听，NapCat 才会连过来
3. 跑 `node qq/probe-napcat.cjs --token <你的token>` 看连接和事件格式

**NapCat 连不上 / 反复掉线**
- 先确认代理：**QQ 登录走代理会触发风控**，把系统代理关掉再登
- 登录态会过期，需要重新扫码：直接双击 `launcher-win10-user.bat`（有窗口才有二维码）

**日志里出现 `PacketBackend 不支持当前QQ版本架构`**
- 可以忽略，见上文

**绑定/查分失败 `user game version unsupported`（game-02）**
- 面板（u.otogame）只认它自己支持的那个游戏版本，这是面板在拒绝这个账号的数据版本，**不是 Bot 的问题**，改代码也救不了。
- 让玩家用**绑定面板的那张卡**在机台上游玩最新版，等面板数据同步后再试。
- 刚玩过最新版仍然是这个提示 —— 说明面板还没跟上机台版本，只能等面板更新（或去问大饼）。

**发图失败**
- 分表约 3600×1800 / 4.5 MiB。若 NapCat 在别的机器/容器里，`file:///` 路径会失效，
  把 `qq-config.json` 里的图片传输改成 base64（见 `qq-onebot.cjs` 的说明）

## 开发

```bash
node qq/build-qq-bot.js     # 跑全部测试 + 打包
```

测试不需要真实 QQ：`mock-onebot.cjs` 会冒充 NapCat 连过来。

- `qq/test-qq-onebot.cjs` —— 传输层：鉴权、动作往返、限流、熔断、去重、重复连接
- `qq/test-qq-entry.cjs` —— 命令解析、群白名单、绑定状态机、回复路由

**改 `takase-core.cjs` 时两边都会受影响**，所以构建闸门里也跑了 Discord 侧的自测。
